Features

Zig Memory Safety

Written in Zig with explicit memory management, integer overflow checks, and no hidden control flow. Reduces memory corruption attack surface.

Sandbox ON Sandbox by Default

Unlike Playwright, Maat runs browsers with sandbox enabled by default. No --no-sandbox unless you explicitly opt out.

Multi-browser Chromium, Firefox, WebKit

Unified API for all major browsers via their native automation protocols (CDP, WebDriver BiDi, Remote Debugging).

Playwright-like Familiar API

browser.launch(), page.goto(), page.click(), page.screenshot() — same concepts, safer implementation.

Example Code

const maat = @import("maat");

pub fn main() !void {
var gpa = std.heap.GeneralPurposeAllocator(.{}){};
const allocator = gpa.allocator();

const browser = try maat.Browser.launch(allocator, .{
.name = maat.BrowserName.chromium,
.headless = false,
.sandbox = true, // sandbox ON by default
});
defer browser.close();

var page = try browser.newPage();
defer page.close();

try page.goto("https://example.com");
try page.screenshot("exemplo.png");

std.debug.print("Title: {s}\n", .{try page.title()});
}

Security

Maat addresses the CVEs affecting the Playwright ecosystem by reimplementing the orchestration layer in Zig. While browser engine vulnerabilities remain, the automation layer is memory-safe and sandboxed by default.

Keep your browsers updated. Sandbox can be disabled only with explicit .sandbox = false (trusted environments only).
