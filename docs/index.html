Zig Memory Safety

Explicit memory management, integer overflow checks, no hidden control flow. Reduces memory corruption attack surface.

Sandbox ON

Unlike Playwright, Maat runs browsers with sandbox enabled by default. No --no-sandbox unless explicitly opted out.

Multi-Browser

Unified API for Chromium, Firefox, WebKit via native protocols (CDP, WebDriver BiDi, Remote Debugging).

// Maat — Browser automation in Zig const maat = @import("maat"); pub fn main() !void { var gpa = std.heap.GeneralPurposeAllocator(.{}){}; defer _ = gpa.deinit(); const allocator = gpa.allocator(); var browser = try maat.Browser.launch(allocator, .{ .name = maat.BrowserName.chromium, .headless = false, .security = .{ .sandbox = true }, }); defer browser.close(); var page = try browser.newPage(); defer page.close(); try page.goto("https://example.com", maat.WaitUntil.load); try page.screenshot("exemplo.png"); const title = try page.title(); std.debug.print("Title: {s}\n", .{title}); }

Security

Maat addresses CVEs affecting the Playwright ecosystem by reimplementing the orchestration layer in Zig. Browser engine vulnerabilities remain, but the automation layer is memory-safe and sandboxed by default.

Sandbox can be disabled only with explicit .security = .{ .sandbox = false } (trusted environments only).
